# An Analogy Has an Expiration Date

**Status:** English working draft | **Theme:** G. Writing, explanation, and representation | **Candidate tags:** philosophy-of-science, education

When we explain a new technology, we often borrow an old one. A computer has memory. An AI agent behaves like a colleague. A robot learns a task through something we call practice. Such analogies are useful because they give a reader a starting point.

The problem appears when the analogy continues to guide our reasoning beyond the relationship it was meant to explain. Calling storage memory can help someone understand that information persists. It does not tell us whether the stored information will be recalled in the right situation. Calling an agent a colleague can help describe a division of work. It does not establish that the agent has the responsibilities or commitments of a colleague.

A good analogy lets us transfer a particular understanding. We should be able to say which relationships travel and where the comparison ends. If I describe a design space as a landscape, for example, the image helps me think about searching among alternatives. I should be more careful if the image leads me to assume every design has a meaningful elevation on a common scale.

This is especially important in arguments about intelligence. A familiar word can make it appear that a machine has acquired all the abilities associated with a human activity, when a particular experiment established only one of them. It can also cause us to miss a capability because the system realizes it in an unfamiliar way.

Analogies should make an unfamiliar problem easier to enter. Once we have entered, we may need to leave the analogy behind and look at the structure of the problem itself.

## Editorial source notes

Reading leads: Dedre Gentner, Structure-Mapping: A Theoretical Framework for Analogy (1983); Lakoff and Johnson, Metaphors We Live By (1980). Develop paired cases where a useful analogy supports a justified inference and an unjustified one.
