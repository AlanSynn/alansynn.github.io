# The Work Between Two Tools

**Status:** English working draft | **Theme:** I. Craft, mechanisms, and fabrication | **Candidate tags:** computer-science, participatory-design

Someone designs a part in one program, exports it, prepares it for fabrication in another program, and assembles it using a set of physical tools. Each of those tools may work well. The difficult part of the project can still lie between them.

A file export normally carries a representation of the design. It may not carry the intentions and relationships that were useful while the design was being edited. A fabrication program might receive a set of surfaces but lose the information that two holes were meant to stay aligned. The maker then has to remember that relationship while preparing the object.

One useful way to study creative systems is to follow a project across its transitions. What does the next tool need to know? What can the person reconstruct easily? Which decisions become difficult to revisit once they cross the boundary? These questions help explain why an apparently small export feature can matter so much in practice.

There are good reasons for tools to use different representations. A manufacturing machine does not need every feature of an artist's drawing program. A compact exchange format can make collaboration and reuse easier. The design problem is to preserve the relationships that matter to the next activity without requiring all tools to share the same internal model.

AI agents can help translate between programs and reconstruct missing context. The value of that assistance will depend on whether the relationships survive the translation. A creative workflow should be understood through the movement of the project as well as through the capabilities of the individual tools.
